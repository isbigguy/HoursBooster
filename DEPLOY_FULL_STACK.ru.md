# HoursBooster v0.0.5: Debian 13, Keycloak и HTTPS

Комплект разворачивает HoursBooster, Keycloak, PostgreSQL и Caddy. Панель и
Keycloak используют разные домены. Снаружи публикуется только TCP 443. Caddy
проверяет сертификаты обоих HTTPS-бэкендов; Keycloak подключается к PostgreSQL
через TLS с проверкой сертификата и имени сервера. HTTP-слушателя и
перенаправления с HTTP нет: открывайте адреса сразу с `https://`.

## 1. Что подготовить

- Debian 13 с Docker Engine и Compose plugin, Git, Python 3 и OpenSSL.
  Docker установите по [официальной инструкции](https://docs.docker.com/engine/install/debian/),
  остальные инструменты: `sudo apt-get install git python3 openssl ca-certificates`.
- Два собственных DNS-имени, например `hours.example.com` и `auth.example.com`.
  Примеры нужно заменить. Один домен с разными поддоменами подходит.
- Публичный IP сервера и доступный входящий TCP 443. Настройте firewall и NAT,
  если сервер находится за роутером. На порту 443 не должен работать другой сервис.
- Электронную почту администратора для ACME и SteamID64 аккаунтов, которым
  разрешён вход в панель через Steam. SteamID64 — 17 цифр из числового адреса
  профиля Steam; ник и короткий адрес профиля для этого не подходят.

Создайте у DNS-провайдера записи:

| Запись                | Значение                      |
| --------------------- | ----------------------------- |
| `hours.example.com` A | публичный IPv4 вашего сервера |
| `auth.example.com` A  | тот же публичный IPv4         |

Эта версия установщика использует один публичный IPv4: удалите AAAA и лишние A
для обоих имён. Центр сертификации может проверять IPv6, если такая запись остаётся. Используйте
режим DNS only без внешнего проксирования CDN: проверка TLS-ALPN-01 должна
достигать именно Caddy на TCP 443. TCP 80 открывать не требуется.
`SERVER_IP` нужен для проверки DNS; он не заменяет домен в HTTPS-адресах.
Публичная установка только по IP этим комплектом не предусмотрена.

## 2. Вписать свои значения

```bash
git clone https://github.com/isbigguy/HoursBooster.git
cd HoursBooster
umask 077
mkdir -p .private/full-stack
cp deploy/full-stack/settings.example.env .private/full-stack/settings.env
nano .private/full-stack/settings.env
```

Заполните приватный файл без кавычек и без пробелов вокруг `=`:

```dotenv
HOURS_DOMAIN=hours.example.com
AUTH_DOMAIN=auth.example.com
SERVER_IP=203.0.113.10
ACME_EMAIL=admin@example.com
STEAM_ALLOWED_IDS=76561198000000001
```

Все значения выше — заглушки. В `HOURS_DOMAIN` впишите домен панели, в
`AUTH_DOMAIN` — домен Keycloak, без `https://`, пути и порта. В `SERVER_IP`
впишите реальный публичный адрес Debian-сервера. В `ACME_EMAIL` впишите свою
почту. В `STEAM_ALLOWED_IDS` впишите свои разрешённые SteamID64; несколько
значений разделяются запятыми. Этот список разрешает вход через Steam и не
добавляет аккаунты для накрутки часов.

При конфликте Docker-подсети задайте свободную `EDGE_SUBNET`, например
`172.29.0.0/24`. Не выбирайте подсеть своей LAN/VPN или существующей Docker-сети.
Не публикуйте заполненный файл настроек и каталог `.private`.

## 3. Установить и запустить

Для обычного rootful Docker выполните из корня репозитория:

```bash
sudo python3 deploy/full-stack/setup.py --settings .private/full-stack/settings.env
```

Установщик проверяет настройки, создаёт случайные пароли и ключи, внутренний
центр сертификации и сертификаты сервисов, затем запускает Compose. Caddy
получает публичные сертификаты Let's Encrypt через TCP 443 и далее продлевает
их автоматически. Корневой внутренний CA не устанавливается в доверенные
сертификаты вашего компьютера и не используется для публичного HTTPS.

В Keycloak автоматически импортируется realm `hours`, конфиденциальный OIDC-клиент
`hoursbooster` и обычный пользователь `operator`. Регистрация посетителей закрыта.
Callback задаётся точно:
`https://ВАШ-ДОМЕН-ПАНЕЛИ/api/auth/callback/keycloak`. PKCE использует S256.
Пароль административного пользователя `bootstrap-admin` создаётся отдельно.

Сгенерированные секреты находятся в `.private/full-stack/state.json` с закрытыми
правами. Посмотрите их локально, например `sudo less .private/full-stack/state.json`:

| Поле                | Для чего                                                       |
| ------------------- | -------------------------------------------------------------- |
| `initial_password`  | первый вход `operator` в панель через Keycloak                 |
| `admin_password`    | административный вход `bootstrap-admin` в Keycloak             |
| `auth_secret`       | ключ сессий и шифрования данных HoursBooster                   |
| `client_secret`     | секрет OIDC-клиента, вручную переносить не нужно               |
| `db_password`       | пароль роли Keycloak в PostgreSQL, вручную переносить не нужно |
| `postgres_password` | отдельный пароль администратора PostgreSQL                     |

Не присылайте содержимое этого файла в чат и не вставляйте его в issues.
Начальный пароль пользователя замените после входа в настройках аккаунта
Keycloak. В консоли `https://ВАШ-ДОМЕН-KEYCLOAK/admin/` войдите в realm `master`
как `bootstrap-admin`, создайте постоянного администратора и удалите временного
bootstrap-администратора согласно инструкции Keycloak. Смена пароля в работающем
Keycloak не выполняется редактированием `state.json`.

## 4. Проверить оба способа входа

1. Откройте `https://ВАШ-ДОМЕН-ПАНЕЛИ`, выберите Keycloak, войдите как `operator`
   с паролем `initial_password`. Возврат в панель происходит автоматически.
2. В панели нажмите **Link Steam sign-in** и подтвердите вход на сайте Steam.
   SteamID64 должен входить в приватный список разрешённых. После привязки
   кнопка Steam на странице входа открывает тот же профиль и его аккаунты.
3. Выйдите и проверьте **Sign in through Steam**. Пароль для этого входа вводится
   на официальном сайте Steam; приложение получает проверенное подтверждение
   OpenID, а не пароль. Ключ Steam Web API для такого входа не нужен.
4. Для добавления аккаунта, который будет работать в сервисе, используйте
   существующую форму добавления Steam-аккаунта внутри панели: пароль и Steam
   Guard либо QR. Подтверждение владельцем остаётся обязательным. Сам вход в
   панель через Steam не выдаёт сервису сессию игрового клиента.

Если первым действием войти через Steam без привязки, будет создан отдельный
профиль. Профили не объединяются автоматически по имени или email. Для общей
панели начните с Keycloak и выполните привязку. Нельзя привязать SteamID,
который уже принадлежит другому профилю.

Вход в панель через Steam использует Steam OpenID 2.0, а вход через Keycloak —
OIDC. Это два разных протокола; сторонний посредник для Steam не используется.

## 5. Управление и резервные копии

Команды из корня репозитория:

```bash
sudo docker compose --project-name hoursbooster --env-file .private/full-stack/compose.env -f deploy/full-stack/compose.yml ps
sudo docker compose --project-name hoursbooster --env-file .private/full-stack/compose.env -f deploy/full-stack/compose.yml restart
sudo docker compose --project-name hoursbooster --env-file .private/full-stack/compose.env -f deploy/full-stack/compose.yml logs --tail=100
```

Повторный запуск установщика с теми же настройками сохраняет созданные секреты.
Импорт Keycloak применяется к новой базе; существующий realm не перезаписывается
при каждом перезапуске. Для изменения доменов, OIDC-клиента и начального
пользователя нужна согласованная перенастройка, а не удаление `state.json`.
Установщик отклоняет изменение сохранённых настроек, включая разрешённые SteamID.
Для изменения списка остановите сервис, сохраните резервную копию, согласованно
обновите `settings.env` и поле `settings.STEAM_ALLOWED_IDS` в приватном `state.json`,
затем снова запустите установщик. Он пересоздаст контейнер приложения с новым
списком, сохранив ключи. Не меняйте остальные поля `state.json` произвольно.

Данные находятся в Docker-томах. Сохраняйте согласованные резервные копии SQLite
HoursBooster, PostgreSQL Keycloak и всего каталога `.private/full-stack`; отдельно
сохраняйте состояние Caddy для ACME. Шифруйте копии. Не удаляйте тома командой
`down --volumes` на рабочем сервере. Потеря `auth_secret` делает сохранённые
Steam-токены нечитаемыми. Доступ к Docker и root равнозначен доступу к секретам.

Внутренние сертификаты действуют 397 дней. До истечения срока обновляйте их
командой ниже; она сохраняет прежний внутренний CA и пересоздаёт контейнеры:

```bash
sudo python3 deploy/full-stack/setup.py --settings .private/full-stack/settings.env --renew-internal-tls
```

Запланируйте продление, например раз в полгода. Не удаляйте рабочую PKI ради перевыпуска.
Публичные сертификаты Caddy продлевает сам при доступном TCP 443.

## Перенос существующей установки

Этот комплект по умолчанию создаёт новые тома. Он не переносит автоматически
базу ранее запущенного сервиса, не меняет владельцев старых Steam-аккаунтов и не
объединяет профили. Перед переносом остановите прежний экземпляр и сохраните
резервные копии его SQLite и исходного `BETTER_AUTH_SECRET`. Для чтения старых
токенов нужен тот же ключ и корректное сопоставление прежних владельцев OIDC.
Не запускайте два экземпляра с одной активной SQLite-базой.

## Диагностика

- Сертификат не выпускается: проверьте A/AAAA обоих доменов, доступность TCP 443
  извне, NAT и отсутствие CDN-прокси. Не отключайте проверку TLS.
- Keycloak не открывается: проверьте `compose ps` и журналы, совпадение домена,
  время сервера и внутренние сертификаты. База должна быть доступна только по TLS.
- Вход Steam отклонён: проверьте SteamID64 в приватном списке, время сервера и
  доступ к `steamcommunity.com:443`. Не публикуйте URL обратного вызова: в нём
  находятся временные параметры подтверждения входа.
- Порт 443 занят: остановите конфликтующий сервис осознанно либо используйте
  отдельный сервер; установщик не должен завершать чужие процессы.

Для разработки есть изолированный режим `--test` с доменами `.test` и частным
тестовым CA. Он предназначен для CI и не заменяет доверенные публичные
сертификаты. Не используйте тестовый режим для публичного развёртывания.

Официальные справочники: [Keycloak reverse proxy](https://www.keycloak.org/server/reverseproxy),
[Keycloak containers](https://www.keycloak.org/server/containers),
[Caddy TLS](https://caddyserver.com/docs/caddyfile/directives/tls),
[Steam OpenID](https://steamcommunity.com/dev).
