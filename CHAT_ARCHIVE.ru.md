# История Steam-чата: рост и архивирование

Часы бустинга сами по себе не создают сообщения. Сохраняются входящие сообщения
и подтверждённые автоответы; автоответ примерно удваивает число записей.

Замер на 10 000 синтетических сообщений, десять аккаунтов, текущие поля и индекс SQLite:

| Размер текста в UTF-8 | Рост БД на сообщение | На 10 000 сообщений |
| --------------------- | -------------------- | ------------------- |
| 100 байт              | около 261 байта      | 2,5 МиБ             |
| 500 байт              | около 741 байта      | 7,1 МиБ             |
| 2000 байт             | около 4161 байта     | 39,7 МиБ            |

Это ориентир, не замер вашего трафика: страницы БД, длина идентификаторов и текст
влияют на результат. Для среднего текста 500 байт **1000 записей/день ≈ 21 МиБ/месяц**,
10 000/день ≈ 212 МиБ/месяц. Считайте суммарно по всем аккаунтам. При отсутствии
переписки таблица не растёт от одного лишь нахождения аккаунта онлайн.

## Что делает ротация

Команда `scripts/archive-chat.mjs` оставляет в рабочей БД **все сообщения последних
30 дней и минимум 1000 последних сообщений каждого аккаунта**. Более старые записи
переносит пакетами до 500 в `/data/chat-archives/chat-ГГГГ-ММ-UUID.json.gz`.
Архив содержит полный исходный текст, ID, время, направление, собеседника, аккаунт
и снимок ID владельца. Пароли, сессии, Steam-токены и настройки не переносятся и не меняются.

Перед удалением пакета из рабочей таблицы команда:

1. Записывает отдельный gzip-файл с правами `0600` в каталог `0700`.
2. Синхронизирует файл на диск, читает обратно и побайтово сравнивает распакованные данные.
3. Синхронизирует запись каталога на Linux и только затем фиксирует транзакцию SQLite.

При ошибке записи, нехватке места, повреждении копии или ошибке SQL текущий пакет
остаётся в БД. Уже завершённые пакеты остаются в архиве. При аварии между записью
архива и фиксацией БД возможны **дубликаты**, а не намеренное удаление единственной копии.
Для сверки используйте ID сообщения вместе с ID аккаунта в пределах одной установки.
Файлы `.partial` — незавершённые попытки; рабочие архивы оканчиваются на `.json.gz`.

**Ничто не удаляется из архивов автоматически.** Программа не пытается определить
«важность» текста. Архивная переписка читается из файлов администратором, в панели
остаются сообщения рабочей БД. Сжатие обратимо, но его степень зависит от текста.

## Запуск на Linux

После установки новой версии выполните из корня `HoursBooster`. Сначала сделайте
[резервную копию](DEPLOY_MAINTENANCE.ru.md). Это обслуживающая команда, **сама по расписанию
она не запускается**. Запускайте, например, раз в месяц; на время операции
остановится только HoursBooster (панель и бустинг), PostgreSQL/Keycloak продолжат работу.

В текущем Bash:

```bash
dc() { sudo docker compose --project-name hoursbooster --env-file .private/full-stack/compose.env -f deploy/full-stack/compose.yml "$@"; }
archive_chat() { dc run --rm --no-deps -T vaporbooster deno run --cached-only --no-prompt --allow-env --allow-sys --allow-read=/app,/data --allow-write=/data --allow-ffi=/app/node_modules scripts/archive-chat.mjs "$@"; }
```

Предпросмотр без изменения БД и создания архивов:

```bash
archive_chat
```

Поле `eligible` — число записей, подходящих под перенос. Для применения выполните
блок в Bash целиком; `trap` запускает остановленный сервис и при обычной ошибке команды:

```bash
(
  set -e
  trap 'dc start vaporbooster' EXIT
  dc stop vaporbooster
  archive_chat --apply
)
```

Проверка результата: `archived` — число перенесённых записей, `files` — имена архивов.
После обрыва SSH/питания проверьте `dc ps` и при необходимости `dc start vaporbooster`.
Команда не запускает `VACUUM`: освобождённые страницы SQLite используются повторно,
но размер существующего файла БД сразу не уменьшается. Упаковка через VACUUM требует
дополнительного места и отдельного окна обслуживания; [описание SQLite](https://www.sqlite.org/lang_vacuum.html).

## Как прочитать и сохранить архив

Архивы лежат в том же `/data`, что и SQLite, поэтому полная копия тома из инструкции
обслуживания включает их. Для отдельного чтения скопируйте их в приватный каталог:

```bash
export_dir=".private/chat-export-$(date -u +%Y%m%dT%H%M%SZ)"
sudo install -d -m 0700 "$export_dir"
sudo docker cp "$(dc ps -aq vaporbooster):/data/chat-archives/." "$export_dir/"
sudo ls "$export_dir"
```

Выберите имя `.json.gz` из списка и подставьте вместо `ИМЯ`:

```bash
sudo gzip -dc "$export_dir/ИМЯ.json.gz" | less
```

`q` закрывает просмотр. Файл — обычный JSON, его можно прочитать независимо от приложения.
Это личная переписка: не публикуйте её и храните внешние резервные копии зашифрованными.
Ротация не заменяет резервную копию: поломка одного диска затрагивает БД и архивы на нём.

Сохранение всей истории навсегда означает рост общего объёма даже после сжатия.
Контролируйте `df -h`; при необходимости переносите проверенные резервные копии
на отдельный диск. Конечный лимит места одновременно с бесконечным хранением
всех сообщений обеспечить нельзя.
